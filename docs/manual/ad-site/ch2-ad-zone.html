第二章广告区域管理

2.1 设计目的与核心概念

广告区域（ad-zone）是站内广告系统的基础设施层。它的设计目的是将"广告展示位置"抽象为可配置的数据实体，使前端无需硬编码广告位，运营人员通过管理后台即可完成广告位的规划、创建和调整。

在广告系统中，广告区域承担三个角色：位置锚点（通过 position 枚举标识页面上的展示位置，前端按位置拉取广告）、展示模式控制（通过 displayMode 决定多条广告内容如何排列展示）、尺寸约束（通过 suggestedWidth/suggestedHeight 向前端传达建议尺寸，确保广告素材比例一致）。

不规划广告区域的后果：前端代码中散布硬编码的广告位逻辑，新增广告位需要前端发版；广告素材尺寸混乱，不同广告在同一位置展示效果参差不齐；无法统一管理广告的上下线，每条广告需要单独处理。正确使用的效果：广告位集中管理，新增/下线广告位无需前端改动；素材尺寸统一，展示效果一致；广告内容与展示位置解耦，运营自主度高。

2.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入运营规划广告位 → 创建 ad-zone 记录 → 关联 site管理后台手动创建
创建/更新填写字段 → 保存 → ad-zone 记录入库Strapi 内容管理器保存操作
下游关联ad-zone → adContents 关联 → ad-content 记录挂载到区域创建 ad-content 时选择所属区域
前端查询前端请求 GET /ads/zones/:position → 服务端按 position + site 查找区域 → 返回区域及其有效内容前端页面加载时自动请求
展示渲染前端组件根据 displayMode 渲染 → 根据 suggestedWidth/Height 约束尺寸前端组件逻辑

区域查询与内容聚合机制

当前端请求 GET /ads/zones/home-banner 时，服务端按以下步骤处理：

  1. 位置匹配 — 根据 position=home-banner 和当前站点上下文查找 ad-zone 记录
  2. 区域校验 — 检查区域是否存在且 isActive 为 true，不满足则返回空
  3. 内容查询 — 查找该区域下所有 isActive 为 true 的 ad-content 记录
  4. 内容过滤 — 过滤掉不在投放时间段内、已达到频次上限的内容
  5. 排序裁剪 — 按 priority 降序、sortOrder 升序排列，根据 displayMode 决定返回数量
  6. 返回数据 — 返回区域信息（含 displayMode、suggestedWidth/Height）和有效内容列表

2.3 适用人群与禁止操作人群

类别角色说明
适用人群站点运营负责人负责站点广告位整体规划，确定每个页面位置需要哪些广告区域
前端开发工程师需要了解 position 枚举值，在页面对应位置嵌入广告组件
广告运营专员在已建区域下创建和管理广告内容
禁止操作人群未经培训的实习生不了解 position 和 displayMode 的含义，可能创建无效区域
内容编辑人员广告区域属于站点基础设施，应由运营或技术角色管理
外部外包人员无系统权限上下文，无法正确关联 site 和规划 position

区域配置最终用途：广告区域一旦创建，将长期存在于系统中，作为广告内容的容器。前端组件依赖区域的 position 值进行广告查询，依赖 displayMode 决定渲染方式，依赖 suggestedWidth/suggestedHeight 约束展示尺寸。因此区域配置需在站点搭建阶段一次规划到位，后续尽量避免修改 position 和 displayMode（修改可能导致前端组件展示异常）。

2.4 字段详解

区域分区概览

区域设计初衷功能价值
基础信息区定义区域的核心标识名称、代码、描述构成区域的身份信息
位置配置区定义区域在页面中的展示位置position 枚举值与前端组件一一对应
展示模式区定义多条内容的排列方式displayMode 决定单条/轮播/幻灯片/堆叠
尺寸约束区向素材制作和前端传达建议尺寸suggestedWidth/Height 统一广告比例
关联配置区建立区域与站点、内容的关联site 关联实现多租户，adContents 承载广告内容
状态控制区管理区域的上下线状态和排序isActive 控制是否生效，sortOrder 控制同位置多区域的排序
name string 必填 广告核心
设计初衷
广告区域的显示名称，用于管理后台列表展示和运营人员识别。
作用原理
仅在管理后台展示，不出现在公开 API 返回数据中。运营人员通过名称区分不同区域。
标准填写规范
使用"页面+位置"的命名格式，如"首页横幅""文章页底部""列表页顶部"。名称应直观反映区域在页面中的位置，便于运营人员快速定位。
错误后果
名称含糊（如"广告1""区域A"）时，运营人员无法快速识别区域用途，导致广告内容配置到错误区域。
code string / unique 必填 API
设计初衷
广告区域的唯一编码，作为区域的业务标识符，用于 API 查询和前端引用。
作用原理
在同一 site 下必须唯一。前端组件通过 code 引用特定区域，管理 API 通过 code 进行 CRUD 操作。
标准填写规范
全小写英文，连字符分隔，格式建议"page-position"，如 home-banner、article-bottom、list-sidebar。与 position 枚举值保持一致或派生自 position。
错误后果
code 不唯一时系统报错无法保存；code 与前端引用不一致时广告无法展示；使用中文或特殊字符可能导致 API 编码问题。
site relation → site 必填 多租户
设计初衷
关联到 site 内容类型，实现多租户数据隔离。每个广告区域必须归属一个站点。
作用原理
公开 API 查询时按当前站点上下文 + position 过滤区域；管理后台列表页可按 site 筛选。
标准填写规范
创建区域时必须选择正确的 site。单站点系统选择默认站点即可；多站点系统需确认区域归属的站点。
错误后果
未关联 site 的区域无法被公开 API 查询到；关联错误 site 的区域会出现在非预期站点上。
position enumeration 必填 广告核心
设计初衷
标识广告区域在页面中的展示位置。前端组件通过 position 值决定在页面的哪个位置渲染广告。
作用原理
枚举值，公开 API GET /ads/zones/:position 使用此值作为路径参数查询区域。前端在对应页面位置使用相同的 position 值请求广告。
position 枚举值详解
枚举值展示位置典型用途
home-banner首页顶部横幅主推活动、品牌展示、重大公告
home-sidebar首页侧边栏推荐内容、合作伙伴、快捷入口
list-top列表页顶部分类推广、筛选引导
article-top文章页顶部文章关联产品推荐、活动入口
article-bottom文章页底部延伸阅读、行动号召、转化引导
article-inline文章正文内嵌段落间广告、原生广告
footer页面底部友情链接、合作伙伴、备案信息
popup弹窗覆盖层首次访问引导、活动弹窗、订阅引导
float悬浮固定位置客服入口、返回顶部、悬浮广告
custom自定义位置特殊场景广告位，前端通过 code 引用
错误后果
position 与前端组件不匹配时广告不会展示；同一站点同一 position 创建多个区域时，API 只返回排序最靠前的一个。
displayMode enumeration 必填 展示
设计初衷
定义多条广告内容在同一区域中的排列展示方式。决定前端组件的渲染逻辑。
作用原理
公开 API 返回此字段，前端组件根据值选择渲染策略：返回一条或多条内容，以何种方式排列。
displayMode 枚举值详解
枚举值展示方式返回内容数适用场景
single单条展示1 条（优先级最高）只需展示一条广告的位置，如首页横幅
rotation轮播展示全部有效内容多条广告按时间间隔轮换展示
slideshow幻灯片展示全部有效内容多条广告以幻灯片形式展示，支持滑动切换
stack堆叠展示全部有效内容多条广告同时垂直排列展示
错误后果
displayMode 与内容数量不匹配时展示效果差：single 模式下配置多条内容只有第一条会展示；stack 模式下内容过多导致页面过长。
suggestedWidth / suggestedHeight integer 选填 展示
设计初衷
向素材制作团队和前端组件传达广告区域的建议尺寸（像素），确保广告素材比例一致。
作用原理
公开 API 返回此字段，前端组件可据此设置容器尺寸；素材制作团队参考此值裁剪图片。
标准填写规范
填写像素值，如 1200x300（首页横幅）、300x250（侧边栏）、728x90（底部横幅）。建议参考 IAB 标准广告尺寸。
错误后果
不设置时素材尺寸无统一约束，不同广告在同一区域展示比例不一致，视觉混乱。
adSlotCode string 选填 广告核心
设计初衷
第三方广告联盟的广告位代码（如 Google AdSense 的 data-ad-slot），用于在区域中嵌入联盟广告。
作用原理
前端组件检测到此字段时，渲染第三方广告联盟的代码而非自管理广告内容。当区域有自管理内容时，此字段作为备选方案。
标准填写规范
填写第三方广告平台提供的广告位标识符。仅在需要接入外部广告联盟时填写。不使用第三方广告时留空。
错误后果
填写错误的广告位代码会导致第三方广告无法展示或展示错误广告；与自管理内容同时存在时可能导致展示冲突。
description text 选填
设计初衷
广告区域的描述说明，帮助运营人员理解区域的用途、位置和展示规则。
作用原理
仅在管理后台展示，不出现在公开 API 中。作为内部文档记录区域的规划意图。
标准填写规范
简要描述区域的页面位置、展示规则和注意事项。如"首页顶部横幅，轮播模式，建议尺寸 1200x300，每次展示 5 秒"。
isActive boolean / default:true 必填 广告核心
设计初衷
控制广告区域是否生效。设为 false 时，该区域不会被公开 API 返回，前端不会展示该位置的广告。
作用原理
公开 API 查询时过滤掉 isActive=false 的区域。设为 false 后，该区域下所有广告内容都不会展示，无论内容自身的 isActive 状态。
标准填写规范
正常使用的区域设为 true。临时下线某个广告位时设为 false（如活动结束后下线弹窗广告位），无需删除区域记录。
错误后果
误将重要区域设为 false 会导致该位置广告完全消失；误将应下线的区域保持 true 会导致过期广告继续展示。
sortOrder integer / default:0 选填
设计初衷
同一 position 下多个区域的排序权重。当同一站点同一 position 存在多个区域时，sortOrder 决定查询优先级。
作用原理
API 查询按 sortOrder 升序排列，返回排序最靠前的区域。默认值为 0。
标准填写规范
正常情况下同一 position 只创建一个区域，sortOrder 保持默认 0。仅在特殊场景（如 A/B 测试、临时替换区域）下创建多个区域并设置不同 sortOrder。
adContents relation → ad-content (oneToMany) 选填 广告核心
设计初衷
区域与广告内容的一对多关联。一个区域可承载多条广告内容，内容通过此关联挂载到区域。
作用原理
在 ad-content 内容类型中设置 adZone 关联时，系统自动在区域的 adContents 列表中添加该内容。API 查询区域时一并返回关联的有效内容。
标准填写规范
无需在区域端手动管理此关联。创建广告内容时选择所属区域即可自动建立关联。在区域列表页可查看该区域下的内容数量。
错误后果
内容未关联到任何区域时无法被 API 返回（孤立内容）；关联到错误区域时广告出现在错误位置。

2.5 标准创建全流程

广告位规划清单

规划项要求用途
页面位置清单列出所有需要广告位的页面和位置确定要创建哪些 position 的区域
展示模式决策每个位置选择合适的 displayMode决定广告的排列方式
建议尺寸规格每个位置的建议宽高（像素）填入 suggestedWidth/suggestedHeight
站点归属确认确认区域归属的 site多站点系统必须明确

填写顺序

  1. 基础信息 — 填写 name（如"首页横幅"）、code（如 home-banner）
  2. 站点关联 — 选择 site，确认归属站点正确
  3. 位置配置 — 选择 position 枚举值，与前端组件对应
  4. 展示模式 — 选择 displayMode，根据位置特点选择 single/rotation/slideshow/stack
  5. 尺寸约束 — 填写 suggestedWidth 和 suggestedHeight
  6. 第三方广告（可选） — 如需接入广告联盟，填写 adSlotCode
  7. 描述说明 — 填写 description，记录区域规划意图
  8. 状态控制 — 确认 isActive=true，设置 sortOrder（默认 0）
  9. 自检 — 对照自检清单逐项检查
  10. 保存 — 保存区域记录

创建前自检清单

  • name 使用"页面+位置"格式，直观可识别
  • code 为全小写英文，与 position 一致或派生自 position
  • site 已正确关联
  • position 枚举值与前端组件预期一致
  • displayMode 与广告内容数量规划匹配
  • suggestedWidth/suggestedHeight 已设置，符合页面布局
  • description 简要说明了区域用途和注意事项
  • isActive 设为 true
  • 同一 site 下同一 position 没有已存在的活跃区域

2.6 发布后闭环运作与禁忌

前端展示效果

广告区域创建后，前端组件通过 GET /ads/zones/:position 获取区域数据和关联的广告内容。组件根据 displayMode 选择渲染策略：single 模式渲染一条内容；rotation 模式渲染轮播组件；slideshow 模式渲染幻灯片组件；stack 模式垂直堆叠渲染所有内容。容器尺寸根据 suggestedWidth/suggestedHeight 约束。

区域管理最佳实践

实践项推荐做法避免做法
命名规范name 使用"页面+位置"格式使用"广告1""区域A"等无意义名称
position 规划站点搭建阶段一次性规划所有 position运营过程中频繁新增 position
displayMode 选择根据内容数量和位置特点选择所有区域统一使用 rotation
尺寸统一同类型区域使用统一建议尺寸每个区域随意设置尺寸
下线方式使用 isActive=false 临时下线直接删除区域记录
修改约束position 和 displayMode 创建后尽量不修改频繁修改 position 导致前端展示异常

字段禁忌写法

字段禁忌写法后果
name纯编号（如"广告区域 01"）运营人员无法快速识别区域用途
code中文或含空格（如"首页横幅 1"）API 编码问题，前端引用困难
position选择 custom 但未与前端约定 code前端无法通过 position 查询到区域
displayModesingle 模式下配置 5 条内容4 条内容永远不会展示，浪费配置
suggestedWidth/Height填写非标准尺寸（如 999x333）素材制作困难，展示比例不协调
禁止操作

1. 频繁修改 position — position 是前端组件与区域的核心关联纽带，修改后前端组件无法匹配，广告消失。如需变更位置，建议新建区域并下线旧区域。

2. 频繁修改 displayMode — displayMode 变更后前端渲染方式改变，可能导致已配置的内容展示异常。如需变更，需同步检查所有关联内容的配置。

3. 删除有内容的区域 — 删除区域后，关联的 ad-content 记录变为孤立数据，无法被 API 查询。应先将内容迁移到其他区域或下线，再停用区域。

4. 同一 position 创建多个活跃区域 — API 只返回 sortOrder 最小的区域，其他区域的内容不会展示，造成配置浪费。

最佳实践总结

广告区域是一次规划、长期使用的基础设施。在站点搭建阶段集中规划所有广告位，创建区域时仔细核对 position 和 displayMode，创建后尽量避免修改。日常运营中只管理广告内容的创建和更新，区域配置保持稳定。如需调整广告位策略，通过停用旧区域、创建新区域的方式实现，保留历史配置可追溯。
