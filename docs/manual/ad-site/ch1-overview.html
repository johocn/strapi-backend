第一章功能概述

1.1 系统架构概述

站内广告系统是 zhao-studio Strapi 插件的核心功能模块，旨在为多站点内容平台提供灵活、可配置的广告管理能力。系统采用广告区域（ad-zone）+ 广告内容（ad-content）两层模型，将"广告展示在哪里"和"广告展示什么"解耦，使运营人员可以独立管理广告位和广告素材，实现一次配置、多端复用。

整个广告系统由三层构成：

架构层职责核心组件
数据层存储广告区域和广告内容数据，维护两者的一对多关系ad-zone 内容类型、ad-content 内容类型、Strapi 数据库
服务层处理广告查询逻辑，包括位置匹配、内容过滤、定时投放、频次控制广告服务（AdService）、公开 API 控制器、管理 API 控制器
展示层前端组件根据 API 返回数据渲染广告，支持多种展示样式和交互效果前端 AdZone 组件、AdContent 渲染器、轮播/视频/弹窗组件

系统的设计理念是声明式配置，响应式展示：运营人员在管理后台声明广告区域的位置和展示模式，为每个区域配置一条或多条广告内容，设置内容类型、样式、定时规则和频次策略；前端通过公开 API 按位置拉取广告数据，根据返回的内容类型和展示样式动态渲染对应组件。整个链路无需前端硬编码广告位，新增广告位只需在后台创建区域记录。

核心设计原则

位置驱动：前端通过位置标识（position）获取广告，而非硬编码广告 ID。内容与区域解耦：一个区域可承载多条内容，内容可在不同区域间复用。多租户隔离：每个站点（site）拥有独立的广告区域和内容，互不干扰。

1.2 广告区域与广告内容的关系

广告区域和广告内容是系统中最核心的两个实体，它们之间是一对多（oneToMany）关系：一个广告区域可以包含多条广告内容，每条广告内容必须归属于一个广告区域。

维度广告区域（ad-zone）广告内容（ad-content）
核心职责定义"广告展示在哪里"以及"以什么模式展示"定义"广告展示什么内容"以及"内容如何呈现"
关键字段position（位置）、displayMode（展示模式）、suggestedWidth/Height（建议尺寸）contentType（内容类型）、images/videoUrl/htmlContent（素材）、displayStyle（展示样式）
数量关系1 个区域 → N 条内容N 条内容 → 1 个区域
生命周期长期存在，一般创建后不频繁变更频繁创建、更新、过期、替换
管理频率低频操作（站点搭建阶段集中创建）高频操作（日常运营持续更新）

两层模型的协作流程

创建广告区域 → 配置位置与展示模式 → 设置建议尺寸
↓
创建广告内容 → 关联到广告区域 → 配置素材与样式 → 设置定时与频次
↓
前端请求 API → 按位置匹配区域 → 过滤有效内容 → 返回广告数据
↓
前端组件渲染 → 根据 displayMode 展示 → 根据 displayStyle 渲染 → 用户看到广告

广告区域的 displayMode（展示模式）决定了多条内容如何被展示：single（单条）只展示优先级最高的一条；rotation（轮播）按时间间隔轮换展示多条；slideshow（幻灯片）以幻灯片形式展示多条；stack（堆叠）同时展示所有内容。广告内容的 displayStyle（展示样式）决定了单条内容的视觉呈现方式（横幅、卡片、弹窗等）。两者协同工作：区域决定"怎么排"，内容决定"怎么画"。

广告区域 ad-zone关系广告内容 ad-content

上表中，"首页横幅"区域包含三条广告内容，由于区域设置为 rotation（轮播）模式，三条内容会按时间间隔轮换展示。运营人员可以随时新增、下线或调整内容的优先级，无需修改区域配置。

1.3 多租户支持

广告系统原生支持多租户（多站点）架构。广告区域和广告内容均包含 site 关联字段，指向 site 内容类型。这意味着每个站点拥有完全独立的广告区域和广告内容集合，互不干扰。

多租户特性实现机制使用场景
数据隔离每个 ad-zone 和 ad-content 记录关联一个 site，API 查询时按 site 过滤站点 A 的首页横幅广告不会出现在站点 B
位置复用不同站点可以使用相同的 position 值（如 home-banner），但各自拥有独立的内容所有站点都有"首页横幅"位，但展示各自的活动广告
独立管理各站点运营人员只管理自己站点的广告，权限可按站点分配站点 A 的运营不需要关心站点 B 的广告配置
统一 API公开 API 通过请求参数或域名识别当前站点，自动返回对应站点的广告前端无需为每个站点写不同的 API 调用逻辑

多站点广告配置示例

多租户场景
企业集团多品牌站点广告管理

某企业集团拥有三个品牌站点：主品牌站（main）、子品牌 A 站（brand-a）、子品牌 B 站（brand-b）。每个站点都有首页横幅、文章页底部、侧边栏等广告位。

三个站点使用相同的 position 值（如 home-banner），但各自拥有独立的内容。前端请求 GET /ads/zones/home-banner 时，API 根据当前站点上下文返回对应的广告数据。

多租户注意事项

创建广告区域和广告内容时，必须关联正确的 site。如果忘记关联 site，该记录可能无法被任何站点的 API 查询到，或出现在非预期的站点上。建议在管理后台列表页使用 site 筛选器确认数据归属。

1.4 数据流转与生命周期

一条广告从创建到展示给用户，经历以下完整生命周期：

广告创建与投放流程

规划广告位 → 创建广告区域 → 设置位置与模式 → 关联站点
↓
准备广告素材 → 创建广告内容 → 关联到区域 → 配置素材样式
↓
设置定时规则 → 设置频次控制 → 激活内容 (isActive=true) → 广告上线
↓
前端请求广告 API → 服务端过滤有效内容 → 按优先级排序 → 返回广告数据
↓
前端渲染广告组件 → 用户看到广告 → 用户点击/关闭 → 行为数据回收

服务端内容过滤逻辑

当前端请求广告 API 时，服务端按以下条件过滤有效广告内容：

  1. 区域匹配 — 根据 position 和 site 查找对应的 ad-zone 记录，确认区域 isActive 为 true
  2. 内容过滤 — 查找该区域下所有 isActive 为 true 的 ad-content 记录
  3. 定时检查 — 过滤掉不在投放时间段内的内容：当前时间需在 startAt 和 endAt 之间（未设置则不限制）
  4. 频次检查 — 根据前端传入的用户标识和 frequencyLimit/frequencyPeriod 判断是否已达到频次上限
  5. 优先级排序 — 按 priority 降序排列，同优先级按 sortOrder 升序排列
  6. 模式裁剪 — 根据区域的 displayMode 决定返回内容数量：single 返回第一条，rotation/slideshow/stack 返回全部

广告下线与替换

下线方式操作适用场景数据保留
停用将 isActive 设为 false临时下线，后续可能恢复保留所有数据
定时过期设置 endAt，到期自动停止展示活动广告自然过期保留所有数据
替换新建内容，将旧内容 isActive 设为 false广告素材更新换代旧内容保留可追溯
删除在管理后台删除记录彻底清除错误数据数据不可恢复
最佳实践

推荐使用停用或定时过期方式下线广告，而非直接删除。保留历史广告数据有助于后续分析投放效果、复用素材配置、追溯投放记录。仅在数据创建错误时使用删除操作。

广告系统的价值闭环

站内广告系统在业务中的价值闭环：广告位规划（确定展示位置）→ 素材制作（准备广告内容）→ 配置投放（设置定时、频次、样式）→ 前端展示（用户看到广告）→ 用户互动（点击/转化/关闭）→ 效果分析（根据互动数据优化后续投放）。广告系统覆盖了前四个环节，为效果分析提供数据基础。

关键理解

广告区域是基础设施，在站点搭建阶段一次性规划好，后续很少变更；广告内容是运营资产，在日常运营中持续创建、更新和替换。理解这一区别，才能正确规划工作流程：先建区域（一次性），再配内容（持续迭代）。
