第四章操作指南（按活动全流程）

本章按一场线下活动的完整生命周期顺序给出操作步骤：前期准备 → 创建配置 → 发布报名 → 现场签到 → 结束回访 → 对账结算 → 归档复用。运营者按阶段顺序执行即可覆盖整场活动。

阶段 0
前期准备 → 阶段 1
创建活动 → 阶段 2
发布报名 → 阶段 3
现场签到 → 阶段 4
结束回访 → 阶段 5
对账结算 → 阶段 6
归档复用

阶段 0：前期准备

创建活动前，先确认以下主档数据已就绪，避免创建时下拉无数据：

  1. 确认活动分类：分类来自 activity-category 分组标签（社会公益、讲座、沙龙、工作坊、培训、读书会、交流会、其他）。若需新增分类，先在资源/标签维护入口补齐
  2. 维护讲师/场地主档：在资源管理中确认本次活动讲师、场地已存在（listLecturers / listVenues），必要时新建。主档新建后会自动同步生成同名标签
  3. 维护活动系列（如需）：系列活动先创建系列，再在活动表单中归属
  4. 确认积分与费用配置：如需报名扣分/奖励/裂变奖励，确认积分规则已配置（详见积分相关手册）
  5. 确认权限：当前账号需具备活动创建/更新权限，且租户已开启活动相关功能开关

阶段 1：创建活动

在运营端进入「线下活动」，点击「新建活动」，按下述区块填写：

1.1 基础信息

  1. 活动标题：必填，用户可见
  2. 活动分类：下拉选择（可不选）
  3. 活动描述：活动详情介绍，展示给 C 端用户
  4. 回放与资料：可关联回放链接/资料内容
  5. 所属系列：下拉选择已建系列（可不选）
  6. 活动时间：开始/结束时间，用于列表展示与签到判断

1.2 报名设置

  1. 报名容量：capacity，满员后自动转候补
  2. 计费模式：一口价（flat）/ 档位（tier）/ 因子（factor），按需选择并配置对应价格档位或因子
  3. 积分价 / 现金价：pointsCost（报名所需积分）与 cashPrice（现金价），按计费模式填写
  4. 收取时点：feeCollectAt——报名时（signup）或签到时（checkin）
  5. 报名开始/结束时间：signupStart / signupEnd，报名时间窗外无法报名
  6. 签到方式：checkinMode——工作人员扫码 / 用户自助 / 两者均可；如开启自助核销并需定位校验，配置 geoEnforced 与半径

1.3 报名表单（formConfig）

  1. 按需添加报名收集字段：设置字段 key / label / type / 是否必填 / 最小值 / 最大值 / 选项
  2. 用户报名时填写的内容保存在报名记录 formData，运营端报名名单可展开查看

1.4 资源与内容解锁

  1. 选择讲师 / 场地：下拉选择（可快速新建后自动选中），系统会做档期冲突预检
  2. 内容解锁：如需报名后解锁文章/课时（preUnlockArticles / preUnlockLessons）或配置学习资料包，在此关联对应内容
  3. 分享裂变奖励：如需拉新，配置 shareRewardPoints
草稿阶段

创建后活动默认处于 draft 草稿状态，C 端不可见。可反复编辑，确认无误后再发布。

阶段 2：发布与报名期

  1. 发布活动：将活动状态转为 signup_open（报名中）。发布后 C 端即可看到并报名，未发布/已归档活动默认被过滤
  2. 关注报名进度：在活动列表查看已报名人数与名额占用；报名高峰并发安全由系统保证
  3. 查看报名名单：进入「报名名单」，按用户查看状态徽章（已报名 active / 候补中 waiting / 已取消 cancelled / 已到场），可展开查看报名表单信息
  4. 候补管理：对候补用户执行「移出候补」（adminCancelSignup）。注意：仅候补状态可移出；对已报名（active）执行移出会被拒绝
  5. 处理取消：用户主动取消 active 报名时，系统自动释放名额并递补最旧的候补转正（自动通知）；候补取消仅置取消，不递补
  6. 临时关闭报名：如需提前截止，可关闭报名（adminClose）

阶段 3：现场签到

  1. 确认签到方式：按活动配置的 checkinMode 安排——工作人员扫码核销，或引导用户自助核销（如开启定位校验，需在活动场地半径内）
  2. 扫码核销：在活动列表进入「扫码核销」，扫描用户报名凭证完成核销
  3. 查看到场记录：切到「到场记录」页，查看已到场用户、到场时间与核销方式（worker_scan / self），用于核对到场率与后续对账
计费时点提醒

若活动配置为 feeCollectAt = checkin（签到时收取），请确保到场签到环节完成扣费/收款，避免漏收。

阶段 4：活动结束

  1. 结束活动：将活动状态转为 ended。系统会对活动期内未签到且未取消的报名用户触发回访提醒，并对已到场用户触发评价/复购相关通知
  2. 沉淀数据：结束后的活动仍可在运营端查看报名名单、到场记录与评价，用于复盘

阶段 5：对账结算

  1. 生成台账：在活动对账/台账入口生成台账快照（ledger），汇总报名、到场与费用数据；如数据有更新可重新生成
  2. 确认讲师/场地结算金额：核对 settleLecturer（讲师结算）、settleVenue（场地结算）
  3. 完成结算：确认金额无误后执行结算（settle）

阶段 6：归档与复用

  1. 归档活动：将已结束（ended）活动转为 archived，归档后 C 端不再展示；归档是长期历史沉淀方式
  2. 恢复活动：如需重新可见，可将 archived 恢复为 ended
  3. 克隆复用：基于已有活动一键克隆，复制讲师/场地关系及分类/表单/资料/结算等配置，用于同类型活动快速开新场
  4. 删除：仅草稿等可安全删除的活动可直接删除，已产生报名数据请谨慎处理
全流程核对清单
  • 创建前：分类/讲师/场地/系列/积分配置就绪
  • 创建时：容量、计费、报名时间窗、签到方式、报名表单、内容解锁配置完整
  • 发布后：转 signup_open，C 端可见可报名
  • 报名期：名单与候补管理到位，满员自动候补、取消自动递补
  • 活动日：按 checkinMode 完成核销，到场记录完整
  • 结束后：转 ended 触发回访/评价，生成台账并完成讲师/场地结算
  • 收尾：归档沉淀，或用克隆快速开启下一场
