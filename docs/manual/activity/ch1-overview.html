第一章手册目的与系统总览

1.1 手册定位与阅读对象

本手册是运营端线下活动功能的使用说明，面向在 h.joho.cn 运营端创建和管理线下活动的操作者，包括：admin（超级管理员）、channel-admin（渠道管理员）、plugin-manager（插件管理员）以及日常运营人员。

手册不是 API 文档，也不讲解源码实现，而是解决三类问题：

  • 这是什么——线下活动在业务中承担什么角色、系统结构如何组成（第一章）
  • 它跟什么有关——活动与标签、积分、课程/官网、系列、资源、渠道/角色、C 端如何联动（第二章）
  • 它怎么用——系统内置的关键机制（第三章），以及按活动全流程的操作步骤（第四章）
阅读建议

初次使用者建议按顺序通读一遍；平时操作遇到疑问，可在第四章按活动所处阶段（准备→创建→发布→签到→结束→结算→归档）定位到对应小节。

1.2 线下活动是什么

线下活动是平台触达会员的线下触点，覆盖讲座、沙龙、工作坊、培训、读书会、交流会等场景。运营者在后台创建活动并开放报名，C 端用户报名、到场签到，活动结束后进行对账结算与归档。

系统围绕三个核心能力构建：

核心能力说明对应数据
活动发布与报名创建活动、配置容量/计费/报名表单、开放报名、候补管理activity + activity-signup
到场与经营闭环扫码/自助核销、到场记录、活动结束后回访评价与复购触发sign-in-record / attendedAt
对账与归档生成台账快照、讲师/场地结算、活动归档与克隆复用ledger / settleLecturer / settleVenue

活动本身还可以与课程/官网内容打通：报名前后解锁指定文章或课时，把"线下到场"转化为"线上内容学习"的引流与复购入口。

1.3 活动全生命周期与状态机

每个活动都有明确的状态，状态决定了当前可执行的操作。运营者通过操作（或系统自动流转）推动活动走完整个生命周期：

草稿 draft → 报名中 signup_open → 进行中 ongoing → 已结束 ended
      ↓ 归档
占位 占位 占位 已归档 archived
占位 占位 占位 ↑ 恢复
占位 占位 占位 已结束 ended
状态含义主要可执行操作C 端可见性
draft草稿，创建后默认状态编辑、删除、转报名中不可见
signup_open报名中，开放报名报名名单、扫码核销、编辑、关闭报名可见，可报名
ongoing进行中（活动开始）报名名单、扫码核销、结束活动可见，按需
ended已结束，触发回访/评价/复购对账结算、归档可见（列表默认过滤草稿与已归档）
archived已归档，历史沉淀恢复（回 ended）、克隆不可见
状态流转注意

归档仅允许从 ended 转入，恢复仅允许从 archived 回到 ended。C 端活动列表默认过滤 draft 与 archived，因此未发布或已归档的活动不会展示给用户。

1.4 角色与权限

活动功能受两类权限约束：

权限维度机制说明
操作权限权限点 activity.read / create / update / delete 等未授权的角色无法看到/创建/编辑/删除活动按钮
渠道作用域channelScope（all / specific）+ channelIds活动可按渠道限定数据范围，管理接口按渠道作用域隔离
可见角色visibleToRoles + 租户开关 roleGate仅当租户开启 roleGate 且填写 visibleToRoles 时，指定角色才可见该活动

管理员路由（/adm/activities/*）均要求渠道作用域与对应权限点，普通用户路由（/my/activity/*）面向 C 端注册用户。

1.5 手册结构说明

四章之间是"理解 → 上手"的递进关系：

  • 第一章（本章）：系统定位、状态机与权限，建立全局认识
  • 第二章：活动与周边系统（标签、积分、课程/官网、系列、资源、渠道/角色、C 端）的关系，回答"改了这里会影响哪里"
  • 第三章：名额并发、候补递补、计费、签到、对账、裂变等内置机制的原理与规则，回答"系统替我把关了什么"
  • 第四章：按活动全生命周期顺序的分阶段操作步骤，回答"我该怎么点"

建议在操作前重点阅读第三、四章；涉及跨系统配置时回查第二章。
