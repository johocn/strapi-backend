第二章与其他设计的关系

线下活动不是孤立功能，它与标签、积分、课程/官网、系列、资源排期、渠道/角色、C 端展示等多个子系统联动。理解这些关系，才能在配置一处时预判对其他地方的影响。

2.1 与标签系统（zhao-tag）的关系

活动通过影子标签联动方案接入统一标签系统，涉及四个标签分组：

标签分组对应资源用途
activity-category活动分类活动分类下拉选项（社会公益、讲座、沙龙、工作坊、培训、读书会、交流会、其他）
activity-venue场地场地下拉与检索
activity-lecturer讲师讲师大下拉与检索
activity-series活动系列系列下拉与检索

联动规则（务必理解，避免误改）：

  • 资源是权威：讲师/场地/系列资源主档新建或改名时，系统自动在对应分组创建/同步同名标签；活动通过这些标签与资源建立索引关系
  • 不回写：在标签页改名不会回写资源主档，资源侧始终是权威数据源
  • 标签检索：活动列表接口支持 documentIds 过滤，通过标签索引检索活动，用于按分类/场地/讲师/系列聚合
操作提醒

活动分类请在表单分类下拉中选择即可（下拉数据来自 activity-category 分组标签）；若要维护分类全集，请在资源/标签维护入口处理，不要直接在标签页造新分类而不落资源。

2.2 与积分系统的关系

活动可深度绑定积分：

积分能力字段时机
报名扣分pointsCostfeeCollectAt = signup 时，报名即扣；checkin 时签到时扣
报名奖励rewardConfig报名成功发放
分享裂变奖励shareRewardPoints用户分享带来的新报名奖励

积分余额校验与扣减由积分服务统一完成，报名记录会保存实际扣点数（pointsCharged）。退款/逆向场景需单独核对积分方法签名与渠道约束，不要假设"报名取消=自动退分"——活动取消仅释放名额并递补候补，积分处理按配置规则执行。

2.3 与课程/官网的关系

活动可通过"内容解锁"打通线上课程与官网文章：

能力字段说明
报名前解锁preUnlockArticles / preUnlockLessons报名（或转正）后自动解锁指定的官网文章 / 课程课时，报名记录写入 unlockInfo
学习资料包learningPackageArticles / learningPackageLessons为到场用户准备的课程/文章资料，可在报名表单或回访中触达

这是"线下到场 → 线上学习 → 复购"转化链路的关键一环，配置时按实际内容选择对应文章/课时即可。

2.4 与活动系列的关系

活动可归属某个活动系列（belongsToSeries），用于组织多场次系列活动（如系列讲座、培训营）：

  • 一个系列下可创建多场活动，通过系列管理聚合查看与排期
  • 支持按系列查询活动、批量生成系列场次（generateSeries）
  • 系列活动共用分类/讲师/场地等资源标签，便于统一运营

2.5 与资源排期的关系

讲师（lecturer）与场地（venue）是活动表单中的两个资源关系字段：

  • 讲师/场地均有独立主档（增删改查），支持档期视图与冲突预检（同一讲师/场地在同一时段是否已被占用）
  • 活动表单从 listLecturers / listVenues 读取下拉选项，选择即建立关系
  • 历史数据中存在 venueName 文本字段的活动，已逐步统一为场地关系，以关系为准

2.6 与渠道/角色的关系

维度字段效果
渠道作用域channelScope（all / specific）+ channelIds限定活动的数据可见渠道，管理接口按渠道隔离
可见角色visibleToRoles + 租户开关 roleGate租户开启 roleGate 且 visibleToRoles 非空时，仅命中角色可见该活动（列表/详情均过滤）；空数组 = 全开放

2.7 与 C 端展示的关系

C 端（h.joho.cn 用户端）通过公开接口消费活动数据：

C 端能力接口说明
活动列表/详情GET /activities / /activities/:documentId默认过滤 draft 与 archived，仅展示已发布活动
费用预览GET /activities/:documentId/fee报名前展示所需积分/现金
报名/取消/签到/评价POST /my/activity/signup、cancel、checkin、/activities/:documentId/reviewC 端用户自助操作
我的报名GET /my/activities我的活动（含候补状态）

因此运营端"发布活动"（转 signup_open）是 C 端可见的前提；活动结束且归档后 C 端不再展示。

一句话总结

活动 = 一个业务实体（activity）挂在资源（讲师/场地/系列）、标签、积分、课程/官网、渠道/角色等多个体系之上。运营者主要打交道的入口是活动表单与资源主档，其余联动由系统自动完成。
