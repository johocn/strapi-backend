第七章合规公示

7.1 设计目的与 GEO 角色

合规公示是官网法律合规和信任建设的底层支撑。它的设计目的是集中展示企业的法律资质、政策文件、合规报告和用户协议，向搜索引擎、AI 模型和用户声明企业的合规状态。

在 GEO 体系中，合规公示承担三个角色：合规信号源（通过结构化数据向 AI 声明企业的合规状态和法律资质）、信任锚点（ICP 备案、营业执照、资质证书等是 AI 评估企业可信度的参考因素）、法律风险隔离（用户协议、隐私政策等公示内容是法律合规的要件）。

不做合规公示的后果：AI 模型在评估企业可信度时缺少合规信号，可能将企业标记为"信息不完整"；用户无法找到隐私政策和用户协议，法律风险增加；搜索引擎对缺少合规信息的站点降低信任评分。正确使用的效果：合规信息通过结构化数据输出，增强 AI 对企业合法性的认知；用户协议和隐私政策公示满足法律合规要求。

7.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入法务文件 / 资质证书 → 内容运营录入法务部门提供文件
创建/更新填写字段 → 保存 → Lifecycle 触发Strapi 保存
Lifecycle 触发搜索引擎推送 → 缓存失效自动
下游输出公开 API → 前端合规页 → sitemap → llms.txt爬虫/前端

与 SEO 全局配置的联动

合规公示中的 ICP 备案号和公安备案号在 seo-config 中也有对应字段（icpNumber 和 publicSecurityRecord）。seo-config 中的备案号写入页面底部全局展示，合规公示中的备案文件作为可点击的详情页。两者互为补充：全局配置保证每页底部都有备案信息，合规公示提供完整的备案文件展示。

7.3 适用人群与禁止操作人群

类别角色说明
适用人群法务负责人最了解法律文件内容和适用范围
合规专员负责资质证书和合规报告的更新
内容运营负责将法务文件录入系统
禁止操作人群市场部可能将营销话术混入法律文件
技术开发不了解法律文件的表述要求
任何非法务背景人员无法判断文件内容的法律准确性

发布内容最终用途：合规公示同时服务于法律合规要求（用户协议、隐私政策的公示是法律要件）、AI 信任度评估（合规信号影响 AI 对企业合法性的判断）、用户信任建设（资质证书展示增强用户信心）、搜索引擎合规评分（ICP 备案等信息影响站点信任评分）。合规内容的准确性直接影响法律风险——错误或过时的合规信息可能导致法律纠纷。

7.4 字段四件套详解

title / content string / text 必填
设计初衷
合规文件标题和正文内容。标题应明确文件类型和主题，正文为法律文件的完整文本。
作用原理
title 写入 <h1> 和结构化数据；content 通过 API 返回前端渲染为合规文件页面；llms.txt 将合规文件链接输出到 Pages 部分。
标准填写规范
title 格式："[文件类型] - [文件主题]"，如"用户协议 - 智造云平台服务条款"。content：法律文件完整文本，使用 HTML 或 Markdown 格式。包含版本号、生效日期、条款内容。
错误后果
内容不完整或与实际法律文件不符可能导致法律纠纷；过时的协议版本可能导致条款无效。
category enumeration 必填
设计初衷
合规文件分类，区分不同类型的公示文件。影响前端展示分组和 AI 分类理解。
作用原理
枚举值：notice（公告）、policy（政策）、report（报告）、certificate（证书）、agreement（协议）。前端按分类分组展示。
标准填写规范
notice：临时性公告（如系统维护通知）。policy：企业政策（如隐私政策、 Cookie 政策）。report：合规报告（如年度合规报告）。certificate：资质证书（如营业执照、ICP 备案）。agreement：用户协议（如服务条款、用户协议）。
错误后果
分类错误导致文件出现在错误的公示分组中；用户协议被分类为公告可能被用户忽略。
effectiveDate / expiryDate date / date 选填
设计初衷
合规文件的生效日期和失效日期。用于管理文件的有效期和提醒更新。
作用原理
前端展示文件有效期；过期的协议文件前端标注"已更新"；管理后台可按到期日排序提醒更新。
标准填写规范
effectiveDate：文件正式生效的日期。expiryDate：文件失效日期（长期有效的留空）。日期格式 YYYY-MM-DD。
错误后果
生效日期填写错误可能导致协议在过渡期无效；未设置 expiryDate 的临时公告长期展示在页面上。
isPinned boolean / default:false 选填
设计初衷
置顶开关。将重要合规文件（如用户协议、隐私政策）固定在列表顶部。
作用原理
前端合规列表页将 isPinned=true 的文件排在最前面展示。
标准填写规范
用户协议、隐私政策等核心文件设为 true。临时公告和报告设为 false。
错误后果
过多文件设为置顶导致置顶功能失效；核心协议未置顶可能被用户忽略。

7.5 标准发布全流程

素材准备

素材要求用途
法务文件文本完整法律文件，经法务审核填入 content
生效日期法务确认的生效日填入 effectiveDate
资质证书图片（如有）扫描件, 清晰可读嵌入 content 中

填写顺序

  1. 基础信息 — 填写 title、slug、content（法律文件全文）
  2. 分类 — 选择 category（notice/policy/report/certificate/agreement）
  3. 有效期 — 填写 effectiveDate 和 expiryDate（如有）
  4. 置顶 — 核心文件设 isPinned=true
  5. SEO — 填写 seoTitle 和 seoDescription
  6. 收录控制 — allowIndex：公开文件设 true，内部文件设 false
  7. 法务审核 — 提交法务负责人审核确认
  8. 发布 — status 改为 published

发布前自检清单

  • title 明确文件类型和主题
  • content 为法务审核通过的完整文本
  • category 分类正确
  • effectiveDate 已填写
  • 核心文件 isPinned=true
  • 法务负责人已审核确认
  • allowIndex 设置正确（公开/内部）
  • 如为证书类，证书图片清晰可读

7.6 发布后闭环运作与禁忌

前端展示与 GEO 效果

合规公示发布后，前端合规页面按分类分组展示所有文件。核心协议（用户协议、隐私政策）置顶展示。合规信息通过 sitemap 和 llms.txt 输出，AI 模型在评估企业合法性时可参考公示的资质和法律文件。ICP 备案号同时通过 seo-config 写入页面底部全局展示。

更新机制

合规文件更新操作规范

用户协议或隐私政策更新时：创建新版本（新记录），将旧版本 status 改为 archived 并设置 expiryDate 为新版本生效日前一天。新版本设 isPinned=true。不要直接修改已发布的旧版本内容——保留历史版本用于法律追溯。

内容禁忌类型

禁止发布的合规内容

1. 未经法务审核的文件 — 未经法务审核的法律文件。后果：可能包含无效条款或法律漏洞，面临法律风险。

2. 过时的协议版本 — 协议已更新但旧版本未归档。后果：用户可能引用过时条款产生纠纷。

3. 敏感信息泄露 — 公示文件中包含商业机密或客户信息。后果：商业损失，可能面临法律赔偿。

4. 营销化表述 — 在法律文件中使用营销话术。后果：法律文件失去法律效力，可能被法院判定为无效。

5. 缺失核心条款 — 用户协议缺失免责条款、争议解决条款等。后果：法律纠纷时缺乏条款保护。
