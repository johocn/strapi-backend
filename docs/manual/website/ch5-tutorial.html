第五章教程/操作指南

5.1 设计目的与 GEO 角色

教程/操作指南是官网知识深度建设的载体。它的设计目的是通过结构化的操作步骤指导用户完成特定任务，同时以 HowTo + VideoObject 结构化数据向搜索引擎和 AI 声明"这是一篇可执行的教程"。

在 GEO 体系中，教程承担三个角色：HowTo 知识图谱节点（HowTo 结构化数据让 AI 在回答"怎么做 XX"类问题时直接引用你的步骤）、视频搜索入口（通过 VideoObject 结构化数据进入 Google 视频搜索结果）、用户留存工具（教程内容关联课程中心，引导用户从免费教程进入付费课程体系）。

不做教程的后果：AI 在回答"XX 怎么操作""XX 教程"类问题时引用第三方平台的教程，你的产品失去使用指导话语权；视频搜索结果中不出现你的教程视频；用户在产品使用中遇到困难时找不到官方指导，转向竞品。正确使用的效果：HowTo 结构化数据在搜索结果中展示步骤富媒体片段，教程视频进入 Google 视频搜索，教程引导用户进入课程中心形成学习闭环。

5.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入产品操作手册 / 课程内容片段 → 创建教程内容运营或教研团队创建
创建/更新填写字段 → 保存 → Lifecycle 触发Strapi 保存
Lifecycle 触发标签索引 → 知识图谱 → 搜索引擎推送 → 缓存失效自动
结构化数据schema-builder 生成 HowTo schema + VideoObject schema前端请求时生成
课程联动教程 ↔ 课程中心（共享知识实体和品牌话术）知识实体关联
下游输出公开 API → 前端教程页 → sitemap → llms.txt爬虫/前端

结构化数据输出

教程页生成两类结构化数据：HowTo（包含步骤名称、描述、预计时间）和 VideoObject（包含视频标题、上传日期、缩略图、内容 URL）。HowTo 数据让 Google 在搜索结果中展示步骤富媒体片段——用户无需点击就能看到前几步，吸引点击。VideoObject 数据让教程视频进入 Google 视频搜索索引。

5.3 适用人群与禁止操作人群

类别角色说明
适用人群产品培训师最了解产品操作流程
教研团队负责教程内容的教学设计
技术文档工程师负责技术类教程的准确性
内容运营负责 SEO 字段和发布流程
禁止操作人群市场部非内容岗不了解操作细节，可能写出不准确的步骤
未实际使用产品的实习生无法验证步骤的正确性
外部兼职无法获取产品最新版本的操作流程

发布内容最终用途：教程同时服务于搜索引擎 HowTo 搜索（通过步骤富媒体片段获取流量）、AI 操作指导引用（HowTo 结构化数据被 AI 直接引用为操作步骤）、视频搜索（VideoObject 数据进入视频索引）、课程中心导流（教程作为免费内容引导用户进入付费课程）。教程的 steps JSON 数据是 AI 最关注的字段——当用户询问"XX 怎么做"时，AI 倾向于引用有结构化步骤的教程。

5.4 字段四件套详解

title / description string / text title 必填 SEO GEO
设计初衷
教程标题和描述。标题应包含"怎么做""操作指南"等 HowTo 类关键词，描述概括教程目标和适用场景。
作用原理
title 写入 HowTo schema 的 name 字段和 <h1>；description 写入 HowTo schema 的 description 和 og:description；llms.txt 使用 title 和 description 作为教程链接的描述。
标准填写规范
title 格式："如何[完成某任务]"或"[产品名] [操作] 完整指南"。15-35 字。description：50-150 字，说明教程目标、适用版本和难度。例如"本教程指导你如何在 30 分钟内完成 MES 系统的初始配置，适用于 v3.0 以上版本。"
错误后果
标题不含"如何/怎么做"等 HowTo 关键词无法匹配 HowTo 搜索；description 不含适用版本信息导致用户按过时教程操作出错。
steps json 必填 GEO
设计初衷
教程操作步骤，以 JSON 数组格式存储。这是 HowTo 结构化数据的核心，也是 AI 引用教程时的直接数据来源。
作用原理
前端渲染为分步展示；HowTo schema 将每个步骤转为 HowToStep 对象（含 name、text、image）；Google 搜索结果可能展示前 3-5 步的富媒体片段。
标准填写规范
JSON 数组格式：[{"name":"步骤标题","text":"详细操作说明","image":"步骤截图URL"},...]。3-15 个步骤。每个步骤的 name 控制在 5-15 字，text 控制在 50-200 字。步骤顺序必须是可执行的操作顺序。
错误后果
JSON 格式错误导致前端渲染异常和 HowTo schema 失效；步骤缺失关键操作导致用户卡住；步骤顺序混乱导致操作失败；无截图的步骤在搜索结果中展示效果差。
videoUrl / thumbnailUrl string 选填 SEO
设计初衷
教程视频 URL 和缩略图 URL。填写后生成 VideoObject 结构化数据，让视频进入 Google 视频搜索索引。
作用原理
videoUrl 写入 VideoObject.contentUrl；thumbnailUrl 写入 VideoObject.thumbnailUrl。Google 视频搜索抓取这些数据后在视频搜索结果中展示缩略图和链接。
标准填写规范
videoUrl：填写视频的公开访问 URL（支持 MP4 直链或 YouTube/B 站嵌入链接）。thumbnailUrl：填写视频缩略图 URL，尺寸 1280x720px，JPG/WebP 格式。两个字段需同时填写。
错误后果
videoUrl 不可访问导致 Google 视频索引失败；只填 videoUrl 不填 thumbnailUrl 导致视频搜索结果无缩略图；URL 指向需要登录才能访问的视频会被搜索引擎跳过。
difficulty enumeration 选填
设计初衷
教程难度等级（入门/中级/高级），帮助用户选择适合自己水平的教程，同时让 AI 在推荐教程时考虑用户水平。
作用原理
前端展示难度标签；教程列表按难度筛选；AI 抓取时通过难度标签理解教程的目标受众。
标准填写规范
beginner：零基础可操作的基础教程。intermediate：需要一定产品使用经验的进阶教程。advanced：面向管理员或开发者的深度教程。根据教程实际需要的先决知识选择。
错误后果
难度标记过低导致新手尝试后失败，体验差；难度标记过高吓退目标用户。
materials / estimatedTime / result json / string / text 选填
设计初衷
materials 是教程所需素材清单（JSON），estimatedTime 是预计完成时间，result 是教程完成后的预期结果描述。三者共同构成 HowTo schema 的补充信息。
作用原理
materials 写入 HowTo.supply；estimatedTime 写入 HowTo.totalTime（ISO 8601 格式）；result 在教程末尾展示并写入 HowTo schema 的 expected结果描述。
标准填写规范
materials 格式：["账号权限","测试数据","操作手册PDF"]。estimatedTime 格式："30分钟"或"PT30M"（ISO 8601）。result：50-100 字描述完成教程后的状态，例如"完成本教程后，你将拥有一个配置完整的生产管理系统，可以开始录入生产订单。"
错误后果
materials 不完整导致用户中途缺少素材无法继续；estimatedTime 与实际差距过大影响用户预期管理；result 不明确让用户不确定教程是否完成。

5.5 标准发布全流程

素材准备清单

素材要求用途
操作步骤文档3-15 步，每步含标题和说明填入 steps
步骤截图每步 1 张, 1280x720px填入 steps 中的 image
视频（可选）MP4 或视频平台链接填入 videoUrl
视频缩略图1280x720px, JPG/WebP填入 thumbnailUrl
封面图1200x630px填入 coverImage
素材清单JSON 数组填入 materials

填写顺序

  1. 基础信息 — 填写 title、slug、description
  2. 操作步骤 — 填写 steps（JSON 数组，含 name/text/image）
  3. 补充信息 — 填写 materials、estimatedTime、result
  4. 难度与分类 — 选择 difficulty、category、tags
  5. 视频资源 — 填写 videoUrl 和 thumbnailUrl（如有视频）
  6. 媒体资源 — 上传 coverImage
  7. 排序 — 设置 order（同分类教程的展示顺序）
  8. 知识图谱 — 选择 mainEntity 和 mentionedEntities
  9. 品牌话术 — 关联 brandVoiceRef
  10. 自检 — 对照自检清单
  11. 发布 — status 改为 published

发布前自检清单

  • title 含"如何/怎么做/指南"等 HowTo 关键词
  • steps JSON 格式正确，3-15 个步骤
  • 每个步骤含 name 和 text，有截图
  • 步骤顺序可执行，无遗漏
  • difficulty 已选择
  • materials 列表完整
  • estimatedTime 合理
  • result 描述明确
  • 视频 URL 可访问（如有）
  • 封面图已上传
  • mainEntity 已关联
  • 实际操作验证步骤正确性

5.6 发布后闭环运作与禁忌

前端展示与 GEO 效果

教程发布后，前端渲染分步教程页面，展示步骤列表、素材清单、预计时间和结果。HowTo 结构化数据让 Google 可能在搜索结果中展示步骤富媒体片段（前 3-5 步），显著提高点击率。VideoObject 数据让教程视频进入视频搜索。教程通过 llms.txt 输出，AI 在回答操作类问题时引用你的步骤。教程关联的知识实体与课程中心共享，用户从教程可跳转到相关课程。

与课程中心的联动

教程到课程的学习闭环

教程是免费内容，承担引流角色。用户通过搜索"怎么做 XX"进入教程页 → 完成教程操作 → 发现需要更系统的学习 → 通过知识实体关联跳转到课程中心 → 注册付费课程。这个闭环中，教程的知识实体和课程的实体重合，确保主题衔接。品牌话术 brandVoiceRef 统一两者的表述方式。

字段禁忌写法

字段禁忌写法后果
title不含 HowTo 关键词（如"产品介绍"）无法匹配 HowTo 搜索
steps填写纯文本而非 JSON 数组HowTo schema 失效，前端渲染异常
steps步骤无截图搜索富媒体片段展示效果差
videoUrl填写需要登录才能访问的视频Google 视频索引失败
estimatedTime与实际差距过大用户预期管理失败，中途放弃

内容禁忌类型

禁止发布的教程内容

1. 未验证的步骤 — 未实际操作验证的教程步骤。后果：用户操作失败，信任度下降，差评传播。

2. 过时操作 — 产品已更新但教程未同步。后果：用户按旧教程操作出错，增加客服压力。

3. 步骤跳跃 — 省略关键中间步骤。后果：新手用户卡住，教程完成率低。

4. 无截图教程 — 纯文字无截图的操作教程。后果：HowTo 富媒体片段无法展示，用户体验差。

5. 与产品功能不符 — 教程描述的操作在产品中不存在。后果：用户质疑产品功能，AI 传播错误操作信息。
