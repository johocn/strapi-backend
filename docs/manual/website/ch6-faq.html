第六章常见问答

6.1 设计目的与 GEO 角色

常见问答是 GEO 体系中与 AI 对话最直接对接的内容类型。它的设计目的是以问答对的形式直接匹配用户的提问——当用户向搜索引擎或 AI 提问时，FAQ 的问答对是最容易被直接引用的内容格式。

在 GEO 体系中，FAQ 承担三个角色：AI 问答直接匹配源（FAQPage 结构化数据中的每个问答对都可能被 AI 直接引用为回答）、语音搜索匹配（FAQ 的自然语言问句格式与语音搜索查询高度匹配）、客服成本降低（常见问题集中展示，减少重复咨询）。

不做 FAQ 的后果：AI 在回答用户关于你产品/企业的问题时使用第三方信息或不回答；语音搜索中完全不出现你的内容；客服重复回答相同问题消耗资源。正确使用的效果：FAQPage 结构化数据被 Google 收录后可在搜索结果中展示 FAQ 富媒体片段（直接展示问答内容），AI 模型在回答相关问题时直接引用你的官方回答。

6.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入客服常见问题收集 / 产品文档 → 创建 FAQ内容运营整理创建
创建/更新填写字段 → 保存 → Lifecycle 触发Strapi 保存
Lifecycle 触发标签索引 → 知识图谱 → 搜索引擎推送 → 缓存失效自动
结构化数据FAQPage schema 生成（含所有问答对）→ 注入 FAQ 列表页前端请求时生成
下游输出公开 API → 前端 FAQ 页 → sitemap → llms.txt（高优先级）爬虫/前端

FAQPage 结构化数据

FAQ 列表页生成 FAQPage 类型结构化数据，包含所有已发布问答对的 Question 和 Answer 对象。Google 收录后可在搜索结果中直接展示问答内容（FAQ 富媒体片段），用户无需点击即可看到答案。这是所有内容类型中搜索结果展示信息量最大的格式。AI 模型在回答用户提问时，优先匹配 FAQ 中的问答对——格式完全一致，引用成本最低。

类别角色说明
适用人群客服负责人最了解用户常见问题
产品经理回答产品功能类问题
内容运营整理和优化问答表述
禁止操作人群销售可能用营销话术替代客观回答
不了解产品的外部写手可能提供不准确的答案

发布内容最终用途：FAQ 同时服务于搜索引擎 FAQ 富媒体片段（搜索结果直接展示答案）、AI 问答直接引用（问答对格式与 AI 回答格式高度匹配）、官网自助服务（用户在 FAQ 页快速找到答案）、语音搜索匹配（自然语言问句匹配语音查询）。FAQ 的答案必须准确简洁——AI 和搜索引擎会直接展示给用户，没有二次点击确认的机会。

6.4 字段四件套详解

question text 必填 SEO GEO
设计初衷
FAQ 的问题文本。应使用用户自然提问的语言，而非产品文档中的正式术语。这是 AI 匹配用户查询的第一信号。
作用原理
写入 FAQPage schema 的 Question.name 字段；作为 FAQ 页面的 <h2> 标题；llms.txt 输出为"FAQ: [question]"格式。搜索引擎和 AI 使用问题文本匹配用户查询。
标准填写规范
使用用户口语化的提问方式。例如"你们的系统支持多语言吗？"而非"系统多语言支持能力说明"。10-40 字。一个问题只问一件事。避免使用内部术语。
错误后果
使用正式术语而非用户语言导致无法匹配搜索查询；一个问题包含多个子问题导致 AI 无法精确匹配；问题过长影响搜索展示效果。
answer text 必填 SEO GEO
设计初衷
FAQ 的回答文本。应直接、简洁地回答问题，这是 AI 和搜索引擎直接展示给用户的内容。
作用原理
写入 FAQPage schema 的 Answer.text 字段；Google 搜索结果 FAQ 富媒体片段直接展示此文本；AI 引用时直接使用此文本作为回答。
标准填写规范
50-200 字。先给出直接答案（是/否/数字），再补充必要说明。避免营销话术。避免"请联系客服"类的回避回答。如果答案需要操作步骤，简要概括并链接到教程。
错误后果
答案过长在搜索结果中被截断；含营销话术导致 Google 拒绝展示 FAQ 富媒体片段；答案不准确被 AI 传播错误信息；回避性回答损害用户体验。
slug / category / tags / order 混合 slug 必填
设计初衷
slug 生成 FAQ 页面 URL；category 分类（产品/价格/技术/服务等）；tags 跨内容关联；order 控制展示顺序。
作用原理
slug 基于 question 自动生成；category 用于 FAQ 页面的分组展示；tags 通过标签索引与其他内容类型关联；order 控制同分类 FAQ 的展示顺序（小的在前）。
标准填写规范
slug：全小写英文，如 support-multi-language。category：选择最相关的分类。tags：2-5 个关键词标签。order：重要 FAQ 设为 0-10，一般 FAQ 设为 50-100。
错误后果
slug 含中文导致 URL 不可读；不设 category 导致 FAQ 列表混乱；order 全部为 0 导致展示顺序随机。

6.5 标准发布全流程

素材准备

素材要求用途
问题文本10-40 字，用户口语化填入 question
答案文本50-200 字，直接简洁填入 answer
分类选择已有分类填入 category
关键词标签2-5 个填入 tags

填写顺序

  1. 问题 — 填写 question（用户语言，10-40 字）
  2. 答案 — 填写 answer（直接回答，50-200 字）
  3. slug — 检查自动生成的 slug，按需修改为英文
  4. 分类标签 — 选择 category，添加 tags
  5. 排序 — 设置 order
  6. 知识图谱 — 选择 mainEntity 和 mentionedEntities（如关联产品）
  7. 自检 — 问题是否用用户语言，答案是否直接准确
  8. 发布 — status 改为 published

发布前自检清单

  • question 使用用户口语化语言
  • question 只问一件事
  • answer 直接回答问题（非回避）
  • answer 50-200 字，无营销话术
  • slug 为全小写英文
  • category 已选择
  • tags 2-5 个
  • order 已设置
  • 答案内容准确，已与产品团队确认

6.6 发布后闭环运作与禁忌

前端展示与 GEO 效果

FAQ 发布后，前端 FAQ 页面按分类分组展示所有问答对。FAQPage 结构化数据包含所有已发布问答对，Google 收录后可在搜索结果中展示 FAQ 富媒体片段——直接在搜索结果页面展示问答内容，无需用户点击。这是所有内容类型中搜索结果信息密度最高的展示形式。AI 模型在回答用户提问时，FAQ 问答对的格式（question + answer）与 AI 的回答模式高度一致，是最容易被直接引用的内容格式。

字段禁忌写法

字段禁忌写法后果
question使用产品术语而非用户语言（如"系统多语言支持能力"）无法匹配用户搜索查询
question一个问题包含多个子问题AI 无法精确匹配
answer含营销话术（如"我们是最优秀的产品"）Google 拒绝展示 FAQ 富媒体片段
answer回避性回答（如"请联系客服了解详情"）用户体验差，AI 无法引用
answer过长（>200 字）搜索结果截断，信息不完整

内容禁忌类型

禁止发布的 FAQ 内容

1. 营销话术回答 — 用广告语言替代客观回答。后果：Google 拒绝展示 FAQ 富媒体片段，AI 不引用。

2. 回避性回答 — 不直接回答问题，引导联系客服。后果：用户不满，AI 无法引用，失去 FAQ 价值。

3. 不准确答案 — 答案与产品实际功能不符。后果：误导用户和 AI，损害品牌信任。

4. 过时答案 — 产品已更新但 FAQ 未同步。后果：用户按旧信息操作出错。

5. 重复问答 — 多条 FAQ 问的是同一件事的不同表述。后果：FAQ 列表臃肿，FAQPage schema 重复。
