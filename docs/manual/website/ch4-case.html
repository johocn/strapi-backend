第四章落地案例

4.1 设计目的与 GEO 角色

落地案例是官网信任建设的核心内容。它的设计目的是通过真实的客户故事和量化成果，向潜在客户和 AI 模型提供社会证明——证明你的产品/方案在真实场景中有效。

在 GEO 体系中，案例承担三个角色：可信度背书（CaseStudy 结构化数据向 AI 声明"这不是广告，是真实案例"）、长尾场景入口（通过"XX 行业 XX 问题解决方案"类长尾搜索获取流量）、产品页转化支撑（与产品双向关联，在产品页展示增强说服力）。

不做案例发布的后果：产品页缺乏社会证明，转化率下降 40-60%；AI 在回答"XX 公司的客户案例""XX 行业有没有成功案例"时找不到你的信息；竞品有案例而你没有，在对比中被淘汰。正确使用的效果：案例页通过"行业+问题+方案"长尾词获取精准流量，案例中的客户名和量化数据增强 AI 引用可信度。

4.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入客户成功故事 → 内容运营整理 → 创建案例手动创建
创建/更新填写字段 → 保存 → Lifecycle 触发Strapi 保存
Lifecycle 触发标签索引 → 知识图谱 → 搜索引擎推送 → 缓存失效自动
产品联动案例 ↔ relatedProducts 关联 → 产品页展示案例双向关联
下游输出公开 API → 前端案例页 → sitemap → llms.txt爬虫/前端

结构化数据输出

案例页生成 CaseStudy 或 Article 类型的结构化数据，包含客户行业、挑战、方案和成果。这些数据让 AI 在回答"XX 行业解决方案"类问题时引用你的案例作为证据。案例的 results 字段（JSON 格式的量化成果）是 AI 最关注的数据点。

4.3 适用人群与禁止操作人群

类别角色说明
适用人群客户成功经理最了解客户使用过程和成果
内容运营负责将客户故事转化为案例内容
市场负责人审核客户授权和敏感信息
禁止操作人群销售人员可能夸大成果或泄露客户隐私
技术开发不了解客户业务背景，无法准确描述挑战和方案
未经授权的实习生无法获取客户授权和准确数据

发布内容最终用途：案例同时服务于搜索引擎长尾流量（通过行业+问题关键词匹配）、AI 可信度引用（CaseStudy 结构化数据 + 量化成果）、产品页转化支撑（关联展示在产品详情页）、客户关系维护（展示客户成功故事增强合作粘性）。案例中的数据必须真实可验证——AI 和用户都可能交叉验证你声明的事实。

4.4 字段四件套详解

title string / maxLength:200 必填 SEO
设计初衷
案例标题，应包含客户行业、核心问题或成果，用于搜索匹配和 AI 引用。
作用原理
写入 <h1> 和结构化数据 name；搜索结果标题；llms.txt 中的链接文本。
标准填写规范
格式建议："[客户名/行业]：[核心问题]的[方案类型]实践"或"[行业]数字化转型：[量化成果]的真实案例"。15-35 字。包含行业关键词和成果数据。
错误后果
标题不含行业关键词无法匹配搜索；不含成果数据降低点击率；泄露不应公开的客户名称引发法律风险。
clientName / clientLogo / clientIndustry string / media / string clientName 必填
设计初衷
客户名称、logo 和所属行业。客户名和 logo 是信任信号，行业用于案例筛选和 AI 分类。
作用原理
clientName 写入结构化数据的提及实体；clientLogo 在案例页展示增强可信度；clientIndustry 用于案例列表的行业筛选和知识图谱分类。
标准填写规范
clientName：使用客户正式名称，未获授权的使用"某XX企业"脱敏。clientLogo：PNG 透明背景，宽度 200-400px。clientIndustry：使用标准行业分类名（如"制造业""医疗""教育"）。
错误后果
未经授权使用客户名称引发法律纠纷；logo 模糊或变形降低专业感；行业填写不规范导致案例筛选失效。
challenge / solution / results text / text / json 全部必填 GEO
设计初衷
案例三要素：客户面临的挑战、你提供的方案、取得的成果。这是 CaseStudy 结构化数据的核心内容，也是 AI 最关注的案例信息。
作用原理
challenge 写入结构化数据描述；solution 作为方案正文展示；results 以 JSON 格式存储量化指标，AI 可直接提取数据点。
标准填写规范
challenge：100-300 字，描述客户的具体痛点和业务影响。solution：300-800 字，分点说明方案的核心组成和实施步骤。results：JSON 数组格式 [{"metric":"生产效率","value":"提升35%","before":"100件/小时","after":"135件/小时"},...]，3-8 个量化指标，每个含指标名、数值、前后对比。
错误后果
challenge 过于笼统（如"效率低下"）无法匹配搜索；results 不是 JSON 格式导致前端渲染异常和 AI 无法提取数据；成果数据不可验证损害可信度。
testimonial / testimonialAuthor / testimonialTitle text / string / string 选填
设计初衷
客户评价内容、评价人姓名和职位。客户原话评价是最强的社会证明。
作用原理
在案例页突出展示；写入结构化数据的 review 字段；AI 抓取时作为客户满意度信号。
标准填写规范
testimonial：50-150 字客户原话，需获客户授权。testimonialAuthor：评价人姓名（可脱敏为"张XX"）。testimonialTitle：评价人职位。
错误后果
未经授权使用客户姓名和原话引发隐私纠纷；编造评价被发现后严重损害品牌信誉。
relatedProducts relation → product (manyToMany) 选填
设计初衷
关联案例中使用的产品，实现案例与产品的双向内链。
作用原理
双向关联：案例页展示使用的产品，产品页展示关联案例。知识图谱建立 CaseStudy-Product 关系。
标准填写规范
关联案例中实际使用的产品，通常 1-3 个。避免关联未在案例中提及的产品。
错误后果
不关联产品导致案例页缺少产品入口，流量无法导向转化；关联不相关产品误导用户。

4.5 标准发布全流程

素材准备清单

素材要求用途
客户授权书书面授权使用客户名称和 logo合规存档
客户 logoPNG 透明背景, 200-400px填入 clientLogo
挑战描述100-300 字，具体痛点填入 challenge
方案描述300-800 字，分点说明填入 solution
成果数据JSON 格式, 3-8 个量化指标填入 results
客户评价50-150 字原话 + 授权填入 testimonial
案例图片封面 + 3-5 张实施过程图填入 coverImage 和 images

填写顺序

  1. 客户信息 — 填写 clientName、上传 clientLogo、填写 clientIndustry 和 clientDescription
  2. 案例三要素 — 填写 title、challenge、solution、results（JSON）
  3. 客户评价 — 填写 testimonial、testimonialAuthor、testimonialTitle
  4. 媒体资源 — 上传 coverImage 和 images
  5. 产品关联 — 关联 relatedProducts
  6. 分类标签 — 选择 tags（行业+产品+场景关键词）
  7. SEO 配置 — 填写 seoTitle、seoDescription
  8. 收录控制 — 确认 allowIndex=true
  9. 知识图谱 — 选择 mainEntity 和 mentionedEntities
  10. 自检 — 对照自检清单
  11. 发布 — status 改为 published

发布前自检清单

  • 客户授权已获取（书面）
  • title 含行业和成果关键词
  • challenge 具体描述痛点（非空泛）
  • solution 分点说明方案组成
  • results JSON 格式正确，含前后对比数据
  • 客户评价已获授权
  • 封面图已上传
  • 关联 1-3 个产品
  • tags 含行业和场景关键词
  • seoTitle 和 seoDescription 已填写
  • allowIndex=true
  • 成果数据可验证

4.6 发布后闭环运作与禁忌

前端展示与联动效果

案例发布后，前端渲染案例详情页，展示客户信息、挑战-方案-成果三段式内容和客户评价。关联的产品页自动展示此案例。案例通过 sitemap 和 llms.txt 输出，搜索引擎和 AI 可发现和抓取。案例的 results JSON 数据是 AI 引用频率最高的字段——当用户询问"XX 产品的效果怎么样"时，AI 倾向于引用有量化数据的案例。

字段禁忌写法

字段禁忌写法后果
title纯品牌宣传（如"XX公司成功案例"）无搜索匹配价值
challenge空泛描述（如"面临数字化转型挑战"）无法匹配具体问题搜索
results填写文本而非 JSON 数组前端渲染异常，AI 无法提取数据
results无前后对比数据（只有"提升35%"）数据可信度低
testimonial编造客户评价被发现后严重损害品牌信誉

内容禁忌类型

禁止发布的案例内容

1. 未经授权的客户信息 — 使用未获授权的客户名称、logo 或评价。后果：面临法律诉讼，客户关系破裂。

2. 虚构案例 — 编造不存在的客户和成果。后果：被发现后品牌信誉归零，AI 标记为不可信来源。

3. 夸大成果 — 数据造假或选择性呈现。后果：客户和 AI 交叉验证发现不一致，信任度下降。

4. 泄露商业机密 — 暴露客户的运营数据、技术架构等敏感信息。后果：面临法律赔偿，客户终止合作。

5. 无量化数据 — 案例只有描述没有数字。后果：AI 不引用（偏好有数据的案例），说服力低。
