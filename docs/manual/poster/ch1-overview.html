第一章功能概述

1.1 系统定位与核心能力

自定义海报功能是 zhao-studio 插件提供的可视化海报模板设计与动态渲染能力。它解决的核心问题是：运营人员需要在不同的推广场景（课程分享、活动裂变、商品推广）中生成带有用户专属邀请码的海报图片，传统做法是为每个场景单独开发前端页面，开发成本高且无法灵活调整布局。

海报模板系统通过模板 + 元素 + 变量三层架构实现"一次设计，动态渲染"。运营人员在管理后台设计海报模板（定义画布尺寸、背景、元素布局），前端通过公开 API 传入变量数据（标题、图片、邀请码等），系统返回完整的元素配置供前端渲染为最终海报图片。

系统的核心能力围绕以下四个维度构建：

核心能力技术实现解决的问题
模板化设计poster-template + poster-element 内容类型运营人员可视化设计海报布局，无需开发介入
变量化渲染必填/选填变量 + resolveTemplate 服务前端传入动态数据，系统自动替换变量并返回渲染配置
邀请码拼接qrContentMode: url_with_invite 模式二维码 URL 自动拼接用户邀请码参数，实现分销追踪
降级容错qrFallbackMode 降级策略 + 变量默认值邀请码缺失时按策略降级，保证海报始终可生成
关键理解

海报模板系统不是图片生成服务，而是布局配置服务。系统返回的是结构化的元素配置（坐标、尺寸、样式、已解析的内容），前端 Canvas 或图片渲染库根据这些配置绘制最终海报图片。这种分离设计使前端可以使用任意渲染技术（Canvas API、html2canvas、Fabric.js 等）。

1.2 系统架构

海报模板功能在 zhao-studio 插件中由以下组件构成：

管理后台 (Ant Design) → Admin API → poster-template 内容类型
↓
poster-element 内容类型 ↔ Strapi Document Service ↔ MySQL 数据库
↓
公开 API (GET / POST) → resolveTemplate 服务 → 变量替换 + 二维码拼接
↓
返回元素配置 JSON → 前端 Canvas 渲染 → 生成海报图片

各层职责说明：

层级组件职责
管理后台PosterTemplatePage.tsx模板列表、模板编辑器、元素可视化编辑、画布预览
Admin APIcontent-api.ts (admin 路由)模板 CRUD、元素 CRUD、批量保存元素、模板克隆
内容类型poster-template / poster-element数据模型定义，存储模板和元素配置
服务层services/poster.ts模板查询、变量解析、二维码拼接、降级处理、默认模板种子
公开 APIcontent-api.ts (public 路由)前端获取模板配置、提交变量渲染请求

1.3 模板与元素的关系

海报模板系统采用一对多的数据模型：一个模板包含多个元素，元素通过 posterTemplate 关联字段归属到所属模板。

内容类型关系说明
poster-templateoneToMany → poster-element一个模板拥有多个元素，通过 elements 关联字段访问
poster-elementmanyToOne → poster-template每个元素必须归属一个模板，通过 posterTemplate 关联字段指向

模板负责定义画布级的属性（尺寸、背景、变量声明），元素负责定义内容级的属性（位置、样式、内容来源）。两者的职责划分如下：

职责维度poster-templateposter-element
画布尺寸canvasWidth / canvasHeight-
背景backgroundColor / backgroundImage / backgroundMode-
变量声明requiredVariables / optionalVariablesisVariable / variableName / defaultValue
元素布局-x / y / width / height / zIndex / rotation / opacity
元素样式-fontSize / fontColor / borderRadius / borderColor 等
元素内容-elementType / content / defaultValue
二维码配置-qrContentMode / qrBaseUrl / qrFallbackMode 等
状态控制isActive / isDefaultsortOrder (元素排序)
注意事项

poster-element 内容类型在 Strapi 内容管理器中设置为 visible: false，即不直接在 Strapi 后台内容管理界面显示。元素的创建、编辑和管理通过海报模板编辑器（PosterTemplatePage）中的元素列表和表单完成，或通过 Admin API 进行批量操作。

1.4 变量系统

变量系统是海报动态渲染的核心机制。每个模板声明两组变量：必填变量（requiredVariables）和选填变量（optionalVariables）。前端调用渲染 API 时必须提供所有必填变量的值，选填变量可以省略。

默认变量定义

变量类别变量名用途绑定元素示例
必填变量
required		title海报主标题（如课程名称）文本元素，variableName=title
description海报描述文字文本元素，variableName=description
image_url主图/封面图 URL图片元素，variableName=image_url
qr_code二维码基础 URL二维码元素，qrBaseUrl 或变量传入
选填变量
optional		market_price市场价（划线价）文本元素，variableName=market_price
sale_price销售价文本元素，variableName=sale_price
invite_code用户邀请码二维码元素，url_with_invite 模式自动拼接

变量解析流程

当前端调用 POST /api/zhao-studio/v1/posters/render 时，系统按以下流程解析变量：

  1. 查询模板 — 根据 templateCode 查找 isActive: true 的模板，同时 populate 关联的 elements
  2. 校验必填变量 — 遍历 requiredVariables，检查前端传入的 variables 是否包含所有必填变量。invite_code 即使在必填列表中也允许缺失（因为它是特殊的可选变量）
  3. 元素内容解析 — 对每个元素判断 isVariable：若为 true，从 variables 中取 variableName 对应的值，缺失时使用 defaultValue；若为 false，直接使用 content 字段
  4. 二维码特殊处理 — 若元素类型为 qrcode 且 qrContentMode 为 url_with_invite，执行邀请码拼接逻辑（详见第四章）
  5. 隐藏元素过滤 — 降级策略为 hide_element 且触发降级时，该元素被标记为 hidden 并从返回结果中过滤
  6. 返回渲染配置 — 返回模板画布配置 + 已解析的元素数组（按 sortOrder 排序）
设计理念

变量系统的设计理念是声明式而非命令式。模板声明需要哪些变量，元素声明绑定哪个变量，系统负责将变量值注入到对应元素。前端只需传入变量键值对，无需关心元素如何布局、内容如何填充。这使得同一套 API 可以服务于任意模板，前端代码与模板设计完全解耦。

1.5 画布坐标系

海报画布采用像素坐标系，原点 (0,0) 位于画布左上角，X 轴向右延伸，Y 轴向下延伸。所有元素的定位基于此坐标系。

坐标属性类型默认值说明
xinteger0元素左上角的水平坐标（px）
yinteger0元素左上角的垂直坐标（px）
widthinteger100元素宽度（px）
heightinteger100元素高度（px）
zIndexinteger0元素层级，数值越大越靠上
rotationinteger0旋转角度（度），正值顺时针
opacitydecimal1透明度，0 完全透明，1 完全不透明

默认画布尺寸

模板的默认画布尺寸为 600 x 1000 像素（宽 x 高），这是一个适合手机端竖屏浏览的海报比例（3:5）。管理后台编辑器中的画布预览会根据实际画布尺寸自动缩放，预览区域最大宽度为 400px，缩放比例 = min(400/canvasWidth, 500/canvasHeight, 1)。

坐标系示意

坐标系示例

假设画布尺寸为 600x1000，一个元素配置为 x=50, y=60, width=500, height=50，表示该元素左上角位于画布坐标 (50, 60) 处，宽度 500px（几乎占满画布宽度），高度 50px。若 zIndex=10，则该元素显示在 zIndex 小于 10 的元素之上。

元素排序规则

元素在返回结果中按 sortOrder 字段升序排列。虽然 zIndex 决定了视觉上的层叠顺序，但 sortOrder 决定了元素在数组中的位置顺序。建议 sortOrder 与 zIndex 保持一致的逻辑：从背景到前景依次递增。

1.6 默认模板种子机制

系统在 zhao-studio 插件启动时（bootstrap.ts）自动执行 seedDefaultTemplate() 方法。该方法检查数据库中是否已存在 isDefault: true 的模板，若不存在则创建一个名为 course_share_default 的默认课程分享海报模板，并附带 6 个预设元素：

元素 Key类型名称变量绑定位置 (x, y)尺寸 (w x h)
titletext课程标题variableName=title(50, 60)500 x 50
cover_imageimage封面图variableName=image_url(50, 130)500 x 300
descriptiontext课程描述variableName=description(50, 460)500 x 60
price_labeltext销售价variableName=sale_price(50, 550)200 x 30
qr_codeqrcode分享二维码qrContentMode=url_with_invite(240, 800)120 x 120
footer_texttext底部提示固定内容: "扫码分享赚积分"(50, 940)500 x 30
种子条件

默认模板种子需要满足两个前提条件：(1) 数据库中不存在 isDefault: true 的模板；(2) 系统中至少存在一个 site-config 站点配置。如果无站点配置，种子过程会跳过并输出警告日志。种子创建成功后输出 [zhao-studio] Default poster template seeded successfully 日志。

使用建议

默认模板 course_share_default 可以直接用于课程分享场景。如果需要自定义布局，建议使用模板克隆功能复制一份默认模板后修改，而非直接修改默认模板。克隆的模板 isDefault 为 false，不会影响种子逻辑。
