第二章模板设计

2.1 模板创建流程

海报模板通过管理后台的"海报模板管理"页面创建。创建流程分为两步：第一步在模板列表页点击"新增模板"填写基础信息，第二步进入模板编辑器添加和配置元素。

创建步骤

  1. 进入海报模板管理 — 在 zhao-studio 管理后台导航中进入"海报模板"页面
  2. 点击新增模板 — 弹出模板创建弹窗，填写模板名称、代码、画布尺寸、背景配置等信息
  3. 保存模板 — 点击确认保存，模板出现在列表中
  4. 进入编辑器 — 点击列表中的"编辑"按钮，进入模板编辑器视图
  5. 添加元素 — 在编辑器右侧"元素列表"中点击"添加元素"，配置元素属性
  6. 保存全部元素 — 点击"保存全部元素"按钮，通过批量保存 API 将所有元素一次性写入
  7. 保存模板属性 — 如有修改，点击"保存模板属性"按钮更新模板配置
模板编码 (code) 的唯一性

code 字段在数据库中设置了 unique: true 约束，是前端获取模板的唯一标识。建议使用有语义的命名，如 course_share_default、activity_promotion_2026、product_detail_v2。前端通过 GET /api/zhao-studio/v1/posters/templates/:code 获取模板配置。

2.2 画布尺寸配置

画布尺寸决定了海报的物理像素大小。所有元素的坐标都基于画布尺寸进行定位。系统提供两个核心字段：

canvasWidth integer / default: 600 必填
设计初衷
定义海报画布的宽度（像素）。所有元素的 x 坐标和 width 不应超过此值。
作用原理
写入数据库后，公开 API 返回此值；前端 Canvas 根据此值设置画布宽度；管理后台预览区域按比例缩放显示。
标准填写规范
默认 600px，适合手机端竖屏海报。常见尺寸：600（微信分享海报）、750（高清竖版）、1080（超高清竖版）。宽度应与目标展示场景的屏幕宽度匹配。
错误后果
设置过小（如 320）会导致海报在高清屏上模糊；设置过大（如 2000）会增加前端 Canvas 渲染性能压力和生成的图片体积。
canvasHeight integer / default: 1000 必填
设计初衷
定义海报画布的高度（像素）。所有元素的 y 坐标和 height 不应超过此值。
作用原理
写入数据库后，公开 API 返回此值；前端 Canvas 根据此值设置画布高度；管理后台预览区域按比例缩放显示。
标准填写规范
默认 1000px，配合 600 宽度形成 3:5 竖版比例。常见比例：3:5 (600x1000)、2:3 (600x900)、9:16 (600x1067)。高度应确保所有元素内容能完整展示。
错误后果
高度不足导致底部元素被截断；高度过大导致海报过长，用户在手机端需要滚动查看，影响分享转化率。

常见画布尺寸参考

场景画布尺寸比例适用场景
微信分享海报600 x 10003:5课程分享、活动推广
高清竖版海报750 x 1060~3:4.2商品详情、品牌宣传
朋友圈海报600 x 9002:3朋友圈九宫格分享
超高清海报1080 x 19209:16全屏展示、视频封面

2.3 背景配置

模板背景是海报的最底层视觉元素，可以是纯色背景或图片背景。背景配置由三个字段组成：

backgroundColor string / default: #FFFFFF 选填
设计初衷
画布的纯色背景色，作为最底层的视觉基底。当未设置 backgroundImage 时，画布以此颜色填充。
作用原理
写入数据库后，公开 API 返回此值；前端 Canvas 以此值填充 fillRect；管理后台预览以此值作为画布背景。
标准填写规范
使用 HEX 格式颜色值，如 #FFFFFF（白色）、#F5F5F5（浅灰）、#1A1A2E（深蓝）。白色背景适合文字密集型海报，深色背景适合图片突出型海报。
错误后果
使用非标准格式（如 RGB 或颜色名称）可能导致部分前端渲染库无法解析；背景色与文字颜色对比度不足会导致可读性差。
backgroundImage string 选填
设计初衷
画布的背景图片 URL。设置后图片覆盖在 backgroundColor 之上，作为画布的视觉基底。
作用原理
写入数据库后，公开 API 返回此值；前端根据 backgroundMode 决定图片的填充方式；管理后台预览以 cover 模式显示背景图。
标准填写规范
填写完整的 HTTPS 图片 URL。图片应预先上传到 CDN 或对象存储。建议图片尺寸与画布尺寸同比例，格式 JPG/WebP，大小不超过 500KB。
错误后果
使用 HTTP 协议的图片 URL 在 HTTPS 页面中会被浏览器拦截（Mixed Content）；图片过大导致海报加载缓慢；图片比例与画布不匹配导致拉伸变形。
backgroundMode enumeration / default: cover 选填
设计初衷
控制背景图片的填充方式，等同于 CSS background-size 属性。
作用原理
前端根据此值决定如何将 backgroundImage 绘制到画布上。仅在设置了 backgroundImage 时生效。
枚举值说明
cover — 等比缩放图片填满画布，超出部分裁剪（默认值，最常用）
contain — 等比缩放图片完整显示在画布内，不足部分留白
stretch — 拉伸图片填满画布，可能导致变形
tile — 平铺重复图片填满画布
标准填写规范
大多数场景使用 cover（背景图填满画布）。如果背景图是图案纹理需要重复，使用 tile。如果需要完整展示背景图内容，使用 contain。
错误后果
stretch 模式会使非等比例的图片变形；contain 模式可能在画布边缘留下 backgroundColor 色块。
背景与背景元素的区别

模板的 backgroundColor / backgroundImage / backgroundMode 是画布级背景，始终位于最底层。此外，元素类型中也有 background 类型（elementType=background），用于在画布背景之上、其他元素之下添加额外的背景层（如半透明遮罩、渐变层）。两者的区别：画布背景是全局的，背景元素是局部的、可定位的。

2.4 变量定义

每个模板声明两组变量列表，以 JSON 数组形式存储。变量定义决定了前端调用渲染 API 时需要传入哪些参数。

requiredVariables json / default: ["title", "description", "image_url", "qr_code"] 必填
设计初衷
声明前端调用渲染 API 时必须提供的变量。系统在解析时会校验这些变量是否全部提供，缺失任何一个（除 invite_code 外）会返回 400 错误。
作用原理
存储为 JSON 数组。渲染服务 resolveTemplate 遍历此数组，检查 variables 中是否存在对应的 key。若缺失（且不是 invite_code），抛出 POSTER_002 错误并列出缺失的变量名。
标准填写规范
JSON 数组格式，如 ["title", "description", "image_url", "qr_code"]。变量名使用 snake_case 命名。默认值包含四个核心变量。根据业务需求可增减，但移除默认变量需确保前端不再传入该变量。
错误后果
将实际需要的变量从 requiredVariables 中移除，会导致前端可能不传该变量，渲染时元素内容为空；将不存在的变量加入 requiredVariables，会导致前端必须传一个无用的变量才能渲染成功。
optionalVariables json / default: ["market_price", "sale_price", "invite_code"] 选填
设计初衷
声明前端可选提供的变量。选填变量缺失时，系统使用元素的 defaultValue 作为回退内容，不会报错。
作用原理
存储为 JSON 数组。渲染服务在解析元素时，若元素的 variableName 对应的变量未传入，使用 defaultValue 或空字符串。
标准填写规范
JSON 数组格式，如 ["market_price", "sale_price", "invite_code"]。invite_code 是特殊选填变量，即使在 requiredVariables 中也允许缺失（因为不是所有用户都有邀请码）。
错误后果
选填变量对应的元素未设置 defaultValue 时，变量缺失会导致元素内容为空，可能影响海报视觉效果。

变量与元素的绑定关系

变量定义在模板级别，变量绑定在元素级别。一个变量可以被多个元素绑定（如 title 变量同时绑定到标题文本元素和一个隐藏的 SEO 元素）。元素的变量绑定通过以下字段实现：

元素字段作用示例
isVariable标记此元素是否为变量驱动true / false
variableName绑定的变量名（必须在 requiredVariables 或 optionalVariables 中声明）"title", "sale_price"
defaultValue变量缺失时的回退值"精品课程", "0"
content非变量元素的固定内容"扫码分享赚积分"

2.5 模板状态控制

isActive boolean / default: true 选填
设计初衷
控制模板是否对前端可见。设为 false 时，公开 API 无法获取此模板，相当于下线。
作用原理
公开 API getTemplate 查询时附带 filters: { code, isActive: true } 条件。isActive 为 false 的模板不会被查询到。
标准填写规范
正式使用的模板设为 true。需要下线但保留数据的模板设为 false。测试中的模板建议设为 false，测试完成后改为 true。
错误后果
误将正式模板设为 false 会导致前端获取不到模板，海报无法生成。误将测试模板设为 true 会导致前端可能获取到未完成的模板。
isDefault boolean / default: false 选填
设计初衷
标记模板是否为系统默认模板。种子机制检查此字段判断是否需要创建默认模板。
作用原理
seedDefaultTemplate() 在启动时查询 filters: { isDefault: true }，若存在则跳过种子创建。克隆模板时，新模板的 isDefault 强制设为 false。
标准填写规范
系统中只应有一个模板的 isDefault 为 true（即种子创建的默认模板）。手动创建的模板保持 false。
错误后果
手动将多个模板设为 isDefault=true 不会报错，但会导致种子逻辑判断紊乱（种子会找到已存在的默认模板并跳过创建）。

2.7 模板克隆

模板克隆功能允许基于现有模板快速创建副本。克隆操作会完整复制模板属性和所有关联元素，适用于"基于默认模板修改"的场景。

克隆逻辑

  1. 查询原始模板 — 根据 ID 查询模板及其所有关联元素
  2. 复制模板属性 — 去除 id、documentId、createdAt、updatedAt、elements 字段，保留其余所有属性
  3. 修改标识字段 — name 追加 "(副本)" 后缀，code 追加 _copy_{timestamp} 后缀，isDefault 设为 false
  4. 创建新模板 — 调用 createTemplate 写入数据库
  5. 复制元素 — 遍历原始模板的每个元素，去除 id、documentId、createdAt、updatedAt、posterTemplate 字段，将 posterTemplate 指向新模板的 documentId，逐一创建
  6. 返回完整模板 — 查询新模板（包含元素）并返回
克隆注意事项

克隆操作的 code 字段追加 _copy_{Date.now()} 时间戳后缀以保证唯一性。克隆后建议立即修改 name 和 code 为有意义的值。克隆的模板 isActive 继承原模板的值，如果原模板是启用的，克隆后也是启用的状态。
