第四章变量与二维码

4.1 变量绑定机制

变量绑定是将模板声明的变量与元素内容关联的机制。通过变量绑定，元素的内容不再硬编码，而是在渲染时根据前端传入的变量值动态填充。

绑定流程

模板声明变量 → 元素绑定变量名 → 前端传入变量值
↓
渲染服务解析 → 变量值注入元素 → 返回已解析配置

绑定字段说明

元素字段作用是否必填示例
isVariable开关：元素是否由变量驱动是（默认 false）true
variableName绑定的变量名，需在模板的 requiredVariables 或 optionalVariables 中声明isVariable=true 时必填"title"
defaultValue变量缺失时的回退内容选填"精品课程"
content非变量元素的固定内容isVariable=false 时使用"扫码分享赚积分"

变量解析逻辑详解

渲染服务 resolveTemplate 对每个元素执行以下解析逻辑：

  1. 判断 isVariable — 若为 false，resolvedContent 直接取 content 字段值
  2. 判断 variableName — 若为 true 但 variableName 为空，resolvedContent 取 defaultValue
  3. 特殊处理 invite_code — 若 variableName 为 invite_code 且前端未传入该变量，resolvedContent 取 defaultValue（允许缺失）
  4. 普通变量取值 — 若 variableName 不为 invite_code，resolvedContent = variables[variableName]，若未传入则取 defaultValue
  5. 二维码特殊处理 — 若元素类型为 qrcode 且 qrContentMode 为 url_with_invite，执行二维码专属的拼接逻辑（见 4.3 节）
invite_code 的特殊性

invite_code 是唯一一个即使在 requiredVariables 中声明也允许缺失的变量。这是因为不是所有用户都有邀请码（如新注册用户、游客访问）。系统在校验必填变量时，会跳过 invite_code 的检查：const missing = requiredVars.filter(v => !variables[v] && v !== 'invite_code')。

4.2 二维码内容模式

二维码元素支持两种内容模式，通过 qrContentMode 字段控制：

qrContentMode: direct enumeration / default 选填
设计初衷
直接模式：使用传入的 qr_code 变量值或元素的 content/defaultValue 作为二维码内容，不做任何处理。
适用场景
二维码内容是固定的 URL 或文本，不需要拼接邀请码。如：公众号关注二维码、客服微信二维码、固定活动页面二维码。
内容来源
遵循通用变量解析逻辑：若 isVariable=true，取 variables[variableName] 或 defaultValue；若 isVariable=false，取 content 字段。
qrContentMode: url_with_invite enumeration 选填
设计初衷
邀请链接模式：将基础 URL 与用户邀请码拼接后作为二维码内容。这是分销场景的核心模式，实现"每个用户的海报二维码都携带专属邀请码"。
适用场景
课程分享海报、商品推广海报、活动裂变海报——任何需要追踪用户邀请关系的场景。
内容来源
基础 URL 优先取 variables.qr_code，若未传入则取元素的 qrBaseUrl 字段。邀请码取 variables.invite_code。
拼接公式
{baseUrl}{separator}{param}={inviteCode}
例如：https://v.joho.cn/share?inviteCode=ABC123

两种模式对比

维度direct 模式url_with_invite 模式
内容来源变量值或 content 直接作为二维码内容基础 URL + 邀请码拼接后作为二维码内容
邀请码处理不涉及邀请码自动拼接 inviteCode 参数
降级策略无（缺失时使用 defaultValue）三种降级模式可选
适用场景固定二维码（公众号、客服号）分销分享二维码（课程、商品、活动）
配置复杂度低（仅需设置内容）中（需配置 URL、参数名、分隔符、降级模式）

4.3 邀请码自动拼接

当 qrContentMode 为 url_with_invite 时，系统自动将用户邀请码拼接到基础 URL 上。拼接过程涉及以下字段：

字段类型默认值作用
qrBaseUrlstring-基础 URL，如 https://v.joho.cn/share
qrInviteParamstringinviteCode邀请码参数名
qrInviteSeparatorstring?URL 参数分隔符

拼接逻辑

当邀请码存在时（variables.invite_code 有值），系统执行以下拼接：

resolvedContent = `${baseUrl}${separator}${param}=${inviteCode}`

具体来说：

  1. 获取基础 URL — 优先取 variables.qr_code，若未传入则取元素的 qrBaseUrl 字段，若两者都为空则使用空字符串
  2. 获取邀请码 — 取 variables.invite_code 的值
  3. 获取分隔符 — 取 qrInviteSeparator，默认 ?
  4. 获取参数名 — 取 qrInviteParam，默认 inviteCode
  5. 拼接 URL — {baseUrl}{separator}{param}={inviteCode}

拼接示例

示例 1：标准拼接
配置项值
qrBaseUrlhttps://v.joho.cn/share
qrInviteParaminviteCode (默认)
qrInviteSeparator? (默认)
variables.invite_codeABC123
拼接结果https://v.joho.cn/share?inviteCode=ABC123
示例 2：已有查询参数的 URL
配置项值
qrBaseUrlhttps://v.joho.cn/course/123?source=poster
qrInviteParaminviteCode
qrInviteSeparator&
variables.invite_codeXYZ789
拼接结果https://v.joho.cn/course/123?source=poster&inviteCode=XYZ789
分隔符选择

当基础 URL 已包含查询参数（即 URL 中已有 ?）时，应将 qrInviteSeparator 设为 & 而非 ?，否则拼接出的 URL 会有两个 ?，导致参数解析错误。当基础 URL 不含查询参数时，使用默认的 ?。

4.4 降级策略

当邀请码缺失时（variables.invite_code 未传入或为空），系统根据 qrFallbackMode 配置决定如何处理二维码元素。这是保证海报始终可生成的容错机制。

qrFallbackMode: base_url_only enumeration / default 选填
行为
仅使用基础 URL 生成二维码，不拼接邀请码参数。resolvedContent = baseUrl
适用场景
默认策略。适用于希望即使没有邀请码也能生成有效二维码的场景。用户扫码后访问基础 URL 页面，不受邀约关系追踪。
示例
baseUrl = https://v.joho.cn/share，invite_code 缺失 → 二维码内容 = https://v.joho.cn/share
qrFallbackMode: default_value enumeration 选填
行为
使用元素的 defaultValue 作为二维码内容。若 defaultValue 也为空，则回退到 baseUrl。resolvedContent = defaultValue || baseUrl
适用场景
适用于有默认二维码内容的场景。如：未登录用户的二维码使用官方推广链接作为默认值。
示例
defaultValue = https://v.joho.cn/official，invite_code 缺失 → 二维码内容 = https://v.joho.cn/official
qrFallbackMode: hide_element enumeration 选填
行为
隐藏该二维码元素。元素被标记为 hidden: true，并在返回结果中被过滤掉，前端不会收到该元素。
适用场景
适用于没有邀请码就不显示二维码的场景。如：仅限已登录用户可见的分享二维码，未登录用户的海报不包含二维码区域。
影响
被隐藏的元素完全不出现在返回的 elements 数组中。前端在渲染时不会为该元素分配画布空间，可能导致海报布局出现空白区域。建议在模板设计时预留该区域的替代内容。

降级策略对比

策略二维码内容元素是否显示推荐场景
base_url_only仅基础 URL显示默认策略，通用场景
default_valuedefaultValue 或 baseUrl显示有默认推广链接的场景
hide_element不生成隐藏（从结果中移除）仅登录用户可见二维码的场景

降级决策流程

邀请码是否存在?
↓
是 → 拼接 URL   否 → 检查 qrFallbackMode
  ↓
base_url_only → 使用 baseUrl
default_value → 使用 defaultValue 或 baseUrl
hide_element → 标记 hidden，从结果中过滤

4.5 容错级别

二维码的容错级别（Error Correction Level）决定了二维码在部分损坏时仍能被正确扫描的能力。通过 qrErrorLevel 字段配置。

级别容错率可恢复数据比例适用场景
L (Low)~7%约 7% 的数据模块可被损坏高质量打印环境，二维码不会被遮挡或变形
M (Medium)~15%约 15% 的数据模块可被损坏默认值，适用于大多数场景
Q (Quartile)~25%约 25% 的数据模块可被损坏二维码上可能叠加 logo 或部分遮挡
H (High)~30%约 30% 的数据模块可被损坏二维码中心叠加 logo，或打印在易损材质上
容错级别选择建议

默认使用 M（15% 容错率），适用于绝大多数场景。如果需要在二维码中心叠加品牌 logo，建议使用 H（30% 容错率），确保 logo 遮挡部分不影响扫描。容错级别越高，二维码的模块密度越大，相同尺寸下可容纳的数据量越少。

4.6 二维码视觉配置

除了内容配置，二维码元素还支持视觉样式定制：

字段类型默认值说明
qrSizeinteger120二维码尺寸（px），决定二维码在元素区域内的绘制大小
qrColorstring#000000二维码前景色（模块颜色），默认黑色
qrBgColorstring#FFFFFF二维码背景色，默认白色
颜色对比度要求

二维码的 qrColor 和 qrBgColor 必须有足够的对比度，否则扫描设备无法识别。推荐使用经典的黑底白字（qrColor: #000000, qrBgColor: #FFFFFF）或反色。如果使用品牌色，确保前景色和背景色的亮度差异足够大。避免使用相近色（如深蓝背景+黑色二维码）。
